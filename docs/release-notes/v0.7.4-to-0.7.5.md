# v0.7.4 → v0.7.5 升级参考（agent prompt）

把下面整段交给你的 coding agent 执行即可完成升级。先由人把 CLI 升到 0.7.5
（`npm i -g @llman-sdd/cli@0.7.5` 或源码检出 `git pull && just link`），再执行本 prompt。

**与 0.7.4 的关键区别：本版含一处字段级 breaking——proposal frontmatter `title`
成为必填**（缺/空 → validate ERROR），prompt 第 3 步做迁移；另有冻结平铺卡格式与
skills 模板措辞更新（第 5 步知会）。

---

```markdown
本项目使用 llman-sdd（spec 驱动开发工作流 CLI）。CLI 已升级 0.7.5，项目 scaffold
可能仍是旧版，且 0.7.5 有一处 breaking 变更需要迁移。请按以下步骤执行并在结束时
报告每步结果：

1. 版本核对
   - 运行 `llman-sdd --version`（应为 0.7.5+）与
     `cat llmanspec/.context/sdd-state.json`。
   - 若 state 的 `cli_version` 落后，继续第 2 步；一致也必须做第 3 步
     （title 迁移与 scaffold 版本无关）。

2. 刷新项目 scaffold（托管块与 skills）
   - 运行 `llman-sdd init --update`。
   - 它只刷新 LLMANSPEC 托管块与 `.agents/skills/llman-sdd-*`；托管块之外的手写
     内容保留不动。0.7.5 的 skills 文案有情态动词措辞修订（见第 5 步），diff
     中 skill 正文变化属预期；确认无手写内容被覆盖即可提交。

3. 【breaking 迁移】为活跃 change 补 frontmatter title
   - 背景：0.7.5 起 proposal frontmatter `title` 必填（一句话概念式标题，不得
     复读 change id），缺失或空串 → `llman-sdd validate` 直接 ERROR，无过渡期。
     0.7.1–0.7.4 则把 `title` 当未知字段拒绝——两版对同一字段互斥，不要在升级
     完成前来回切换 CLI 版本。
   - 迁移：为 `llmanspec/changes/` 下（`archive/` 除外）每个含 proposal.md 的
     change 的 frontmatter 补一行 `title: <非空标题>`（正文有 H1 用 H1 文本，
     没有先写 `TODO` 占位）。可用下面内联脚本一次性完成（幂等，已有非空 title
     的自动跳过）：

     ```bash
     python3 - <<'PY'
     import re
     from pathlib import Path
     root = Path('llmanspec/changes')
     for p in sorted(root.glob('*/proposal.md')):
         if 'archive' in p.relative_to(root).parts: continue
         t = p.read_text()
         m = re.match(r'^---\n(.*?)\n---\n', t, re.S)
         if not m: continue
         fm = m.group(1)
         cur = re.search(r'^title:\s*(.+)$', fm, re.M)
         if cur and cur.group(1).strip().strip('"\'') != '': continue
         h1 = re.search(r'^# (.+)$', t, re.M)
         title = h1.group(1).strip() if h1 else 'TODO'
         p.write_text(t.replace(m.group(0), f'---\ntitle: {title}\n{fm}\n---\n', 1))
         print(f'[backfill] {p.parent.name}: {title}')
     PY
     ```

   - `changes/archive/` 下的 proposal 免检，不需要动。

4. 校验
   - `llman-sdd validate --all --strict` 必须全绿；若仍有
     `requires a non-empty 'title'` ERROR，说明第 3 步漏了对应 change，补上后重跑。
   - 项目若有自己的门禁（`just qa` 或等价），跑一遍确认无回归。

5. 0.7.5 行为变化知会（多数无需动作）
   - **冻结平铺卡转单文档纯 YAML**：此后 `archive freeze` 生成的
     `<YYYY-MM-DD>-<id>.yaml` 不再带 `---` 围栏，标准 YAML 解析器可直接读；
     卡 title 取 frontmatter `title` 非空优先、正文 H1 回退。**存量围栏卡无需
     迁移**（graph 依赖边双格式兼容），存量空 title 卡不补救（正文在冷备与
     git 历史中可查）。
   - **skills 措辞修订**：「MUST/SHALL 行为合约变更」「必须/必须」等代称统一为
     「行为合约（需求语义）变更」；若你的 agent 对 skill 文案敏感，重读
     `.agents/skills/llman-sdd-propose`（description 与规模判据段措辞已变）。
   - **`change new` 骨架**预填 `title: TODO` 非空占位，新起草 change 直接过门，
     充实 proposal 时改写即可。

约束：全程不得 push、不得改动 `llmanspec/specs/**` 行为合约、不得删除 LLMANSPEC
托管块标记、不得动 `changes/archive/**`。遇报错原样贴出并停止。
```
