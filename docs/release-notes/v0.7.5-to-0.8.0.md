# v0.7.5 → v0.8.0 升级参考（agent prompt）

把下面整段交给你的 coding agent 执行即可完成升级。先由人把 CLI 升到 0.8.0
（`npm i -g @llman-sdd/cli@0.8.0` 或源码检出 `git pull && just link`），再执行本 prompt。

**与 0.7.5 的关键区别：本版为 breaking 次版本——spec 头契约收缩（`# scope:` /
`# reviewed-through:` 不再被解析）、`validate --json` 去 `staleness` 键、`review`
信号集收缩**。prompt 第 2 步做存量头迁移；0.8.0 起同类迁移手册已内建
（`llman-sdd project migrate prompt --version-expr '<from>-><to>'`），本文件即其
0.7.5→0.8.0 条目的展开。

---

````markdown
本项目使用 llman-sdd（spec 驱动开发工作流 CLI）。CLI 已升级 0.8.0，项目内 spec
头部带有已被退役的治理注释行，需要一次性迁移。请按以下步骤执行并在结束时报告
每步结果：

1. 版本核对
   - 运行 `llman-sdd --version`（应为 0.8.0+）并
     `cat llmanspec/.context/sdd-state.json`。
   - 若 state 的 `cli_version` 落后，第 3 步的 `init --update` 会将其对齐。

2. 【breaking 迁移】剥除存量治理头行
   - 先预览：`llman-sdd project migrate strip-legacy-headers --dry-run`。
   - 确认列表后正式执行：`llman-sdd project migrate strip-legacy-headers`。
   - 它删除 `llmanspec/specs/**` 内行首 `# scope:` / `# reviewed-through:` 注释
     行（幂等，重复执行报告零改动）；capability/purpose 头与规则正文不动。
   - 若输出为 0 file(s)，说明本仓无存量头，直接进第 3 步。

3. 刷新项目 scaffold（托管块与 skills）
   - 运行 `llman-sdd init --update`。
   - 0.8.0 的 skills 变化：apply/verify 不再注入 review-stamp 段（复核改为
     「读 spec 即判断」，不写任何标记）；头注释示例只剩 capability/purpose 两行。
     diff 中 skill 正文变化属预期；确认无手写内容被覆盖后提交。

4. 全量验证
   - `llman-sdd validate --all --strict` 必须全绿。
   - 项目自身测试套件（本仓为 `bun test tests/bdd`，其他仓按其
     `specs.check_command`）照常运行。
   - 结构性抽查：`llman-sdd review` 的 signal kind 应恰为
     unbound/locked/validate（无 stale）；`llman-sdd validate --specs --json`
     载荷不含 `staleness` 键。

5. 行为变化知会（写入交接说明）
   - spec 头部只维护 `# capability:` 与 `# purpose:` 两行；历史
     `# scope:`/`# reviewed-through:` 行已是普通注释,不再有任何工具语义。
   - spec 与代码的关联判定由 context 检索（pageindex 索引）承担;历史复核记录
     以 git 台账为准（`git log -- <spec>`,提交均为 `archive(sdd): <id>`）。
   - 旧「复核写印章 / commit subject 引用复核 id」纪律随 0.8.0 skills 作废,
     不要再沿用。
````

## 不迁移会怎样

不执行第 2 步也可运行：存量头行降级为普通注释,解析与校验不受影响。但 skills
文案与实际头格式将长期不一致,建议完成迁移。
